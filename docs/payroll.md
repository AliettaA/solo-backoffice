# 給与・源泉徴収の設定

既存環境へ反映する際は、通常のバックアップを取ったうえでプロジェクト内で次を実行します。

```sh
php artisan migrate
php artisan db:seed --class=WithholdingTaxBracketSeeder
```

全体の DatabaseSeeder を既存環境で再実行する必要はありません。税額表の専用シーダーは繰り返し実行できます。

1. 従業員ページで区分（専従者／従業員）と扶養人数を設定して保存します。既存の従業員の区分は「従業員」です。
2. 在籍中の専従者は月額80,000円で、勤怠がなくても給与画面に表示されます。従業員は対象月の勤怠に保存された給与額を合計します。
3. 給与画面で支払日と市県民税を入力すると、源泉徴収額と差引支給額を再計算します。社会保険料の自動算定は行いません。
4. 登録時にもサーバーで再計算し、支給額、控除額、源泉徴収額、差引支給額、扶養人数を保存します。登録後に従業員の扶養人数を変えても支払履歴は変わりません。
5. 従業員は労務費、専従者は給料を借方、差引支給額を現金または銀行預金、源泉徴収額を源泉所得税預り金、社会保険料等を預り金、市県民税を市県民税預り金として貸方へ記録します。

## 計算条件と対応範囲

- 月1回払い、扶養控除等申告書提出者の甲欄。乙欄・日額表・賞与・年末調整は対象外です。
- 支払日が2025年・2026年の給与について、国税庁の該当年の月額表を使用します。支払日の初期値は対象月末日です。実際の日付へ変更してください。
- 既存の税額表データに合わせ、社会保険料等控除後332,000円未満、扶養親族等0〜7人に対応します。対象外の金額・年や税額表未登録時は登録を止め、エラーを表示します。
- 扶養人数は家族の総人数ではなく、税額表で使用する「扶養親族等の数」です。
- 同一従業員・対象月の二重登録を防ぎます。分割払いには対応していません。変更時は既存の記録を削除して再登録します（対応する仕訳も削除されます）。
- 旧データで控除前支給額が0のものは、従来の支払額を支給額として表示します。過去の記録を自動で書き換えません。
- 専従者の在籍状態と区分は現在のマスタを参照します。過去月の未登録給与を作成する場合は対象者の在籍状況を確認してください。

出典: https://www.nta.go.jp/publication/pamph/gensen/zeigakuhyo2026/data/01-07.pdf

勤怠画面の従業員別集計には、対象月の年・現在の扶養人数・社会保険料等0円で算定した源泉所得税と差引支給額の目安を表示します。給与登録や仕訳作成は行いません。過去年の扶養人数が現在と異なる場合にはマスタの人数を確認してください。

2025年の出典: https://www.nta.go.jp/publication/pamph/gensen/zeigakuhyo2024/data/01-07.pdf

## 検証

```sh
./vendor/bin/phpunit --filter=PayrollTest
```

本番DBを使用せず、SQLiteのメモリ上に給与・仕訳の実際のマイグレーションを適用して検証します。既存の無関係なMySQL専用マイグレーションは対象外です。
